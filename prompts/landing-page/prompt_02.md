## 1. REVISÃO DO TOM

A landing page é um experimento de Product Discovery. Ela não deve parecer que estamos vendendo um produto já lançado.

O tom deve ser:
- profissional;
- claro;
- confiável;
- simples;
- próximo de pequenos empreendedores;
- sem linguagem excessivamente corporativa ou técnica.

Evite palavras como:
- revolucionário;
- inteligente;
- definitivo;
- garantido;
- automático, quando implicar uma funcionalidade que ainda não foi validada;
- resultados garantidos;
- economia garantida.

Não mencionar IA como argumento principal da página. O foco deve ser o problema e o benefício percebido pelo usuário.

## 2. HERO

Mantenha exatamente esta estrutura:

Título:
"Saiba quanto seu negócio realmente está dando de lucro."

Subtítulo:
"Registre suas receitas e despesas de forma simples e tenha uma visão clara de quanto entrou, quanto saiu e quanto realmente sobrou."

Texto complementar:
"Sem planilhas complicadas. Sem precisar entender contabilidade."

Garanta que o título seja o elemento visual dominante da primeira tela.

O título deve ocupar uma largura confortável e não ficar excessivamente quebrado em várias linhas.

O dashboard à direita deve permanecer visualmente secundário ao título, funcionando como demonstração visual da solução.

## 3. NAVEGAÇÃO

Revise os itens de navegação criados anteriormente.

Mantenha uma navegação mínima e coerente com uma landing page de uma única página.

Use apenas referências às seções existentes, por exemplo:
- Problema
- Como funciona
- Solução
- Para quem é

Não criar páginas adicionais.

## 4. SEÇÃO DO PROBLEMA

Revise os textos dos três cards para que apresentem dores, não funcionalidades.

Use exatamente estes títulos:

"Quanto realmente sobrou?"

"Onde o dinheiro está indo?"

"Seus preços estão certos?"

As descrições devem ser curtas, concretas e relacionadas às dificuldades identificadas durante nossa descoberta.

Não afirmar que todos os pequenos empreendedores possuem esses problemas.

Evitar frases absolutas como:
"Você não sabe..."
"Seu negócio está perdendo dinheiro..."
"Você está sempre no prejuízo..."

Preferir linguagem como:
"É fácil perder a clareza sobre..."
"Pode ser difícil entender..."
"Sem uma visão clara..."

## 5. PROPOSTA DE VALOR

Manter o título:

"Um jeito mais simples de entender o dinheiro do seu negócio."

Manter os três passos:

01 — Registre
02 — Entenda
03 — Decida

As descrições devem ser objetivas.

Não transformar esses passos em promessas de funcionalidades avançadas.

## 6. SEÇÃO "DO REGISTRO À CLAREZA"

Manter a sequência:

ENTRADA → ORGANIZAÇÃO → VISÃO

Os exemplos devem permanecer fictícios.

Use exemplos simples de movimentações:

"Recebi R$ 450 de um serviço"

"Gastei R$ 120 com material"

Na etapa ORGANIZAÇÃO, mostrar visualmente que as movimentações são agrupadas e organizadas.

Na etapa VISÃO, mostrar receitas, despesas e resultado.

O objetivo dessa seção é explicar o conceito em poucos segundos.

## 7. MOCKUP FINANCEIRO

Preserve o dashboard existente.

Verifique apenas se:

Receitas = R$ 4.850
Despesas = R$ 2.420
Resultado = R$ 2.430

As categorias devem continuar somando exatamente R$ 2.420.

Mantenha:

Materiais: R$ 980

Outros: R$ 280

Mantenha também o aviso:

"Exemplo ilustrativo — dados fictícios."

O dashboard deve parecer um protótipo visual de uma solução futura, não uma tela de um produto já disponível.

## 8. SEÇÃO "PARA QUEM É"

Manter:

"Feito para quem trabalha por conta própria."

Manter os três grupos:

Prestadores de serviço
Profissionais autônomos
Pequenos negócios

As descrições devem ser curtas.

Não afirmar que a solução já atende ou resolve os problemas desses grupos.

## 9. CTA FINAL

Manter:

"Quer experimentar essa ideia antes de ela ser lançada?"

Texto:

"Estamos testando uma forma mais simples de ajudar pequenos empreendedores a entender melhor suas finanças."

Botão:

"Quero participar do teste gratuito"

O botão deve ser visualmente destacado, utilizando o azul-marinho definido na identidade.

Ainda NÃO configurar o link.

## 10. IDENTIDADE VISUAL

Faça uma revisão geral para garantir:

- fundo branco/off-white predominante;
- azul-marinho como cor principal;
- azul secundário apenas como apoio;
- verde financeiro utilizado de maneira discreta;
- textos em tons escuros e cinza;
- bordas sutis;
- sombras muito leves;
- cantos levemente arredondados;
- ícones lineares consistentes;
- bastante espaço em branco;
- nenhuma seção visualmente carregada.

Não adicionar:
- gradientes fortes;
- excesso de ilustrações;
- elementos 3D;
- fotos genéricas;
- gráficos decorativos sem função;
- excesso de cores.

## 11. HIERARQUIA

Revise toda a página garantindo a seguinte ordem de percepção:

1. Problema
2. Clareza da proposta
3. Como funciona
4. Visualização da solução
5. Convite para participar do teste

O visitante deve entender o conceito sem precisar ler todos os textos.

## 12. MOBILE

Agora faça uma revisão da versão mobile no próprio Canva.

Não crie uma nova versão.

Verifique especificamente:
- títulos não cortados;
- textos não sobrepostos;
- cards com espaçamento adequado;
- dashboard legível;
- botões com tamanho confortável;
- elementos horizontais adaptados para telas pequenas;
- ausência de elementos saindo da área visível;
- espaçamento vertical consistente.

Se algum elemento horizontal ficar apertado no mobile, reorganize apenas esse elemento para uma disposição vertical.

Não adicione novas funcionalidades.

Não configure links.

Não publique.

1. quais ajustes foram realizados;
